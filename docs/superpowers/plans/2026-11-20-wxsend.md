# wxsend 自动发送 Implementation Plan

> **执行状态：✅ 完成（2026-11-22 00:23 联机复验通过）** — 全分支终审 With-fixes → 修复波 `d6938c5..0e63fca` 复审全项 ADDRESSED；测试 69+36 全绿；同目标背靠背两次发送均 exit 0 + RECEIPT + 监听自捕获。机制终形：置顶行点击 → 剪贴板粘贴（管道安全包装）→ 发送按钮点击 → 尾随点击关会话（toggle 不变式）→ local_id 增长回执。飞书问进度请读本文件头部与 `tools/wechat-send/README.md`。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CLI 驱动微信 Linux 客户端向 roster 白名单目标发送纯文本报告，三重校验 + 数据库回执确认，杜绝错发。

**Architecture:** GUI 自动化（ydotool uinput + wl-clipboard）执行「搜索→进会话→粘贴→回车」序列；发送前用 contact.db 校验备注唯一性并算出预期表名，发送后轮询 `Msg_<md5(ident)>` 表确认落库。所有 GUI 调用经 argv 构建器隔离，纯逻辑全部可单测；真实环境只在 Task 6/7 介入。

**Tech Stack:** Python 3.13（stdlib only，roster 用 JSON 不引 PyYAML）、ydotool、wl-clipboard、sqlcipher CLI、unittest（项目既有测试框架）。

**Spec:** `docs/superpowers/specs/2026-11-20-wxsend-design.md`

## Global Constraints

- 不修改微信二进制/进程内存（设计明确排除 hook 方案）
- 中文/多行文本一律经剪贴板粘贴，禁止键盘逐字模拟
- 所有新文件放 `tools/wechat-send/`，复用 `tools/wechat-monitor/` 的 `crypto/content_parser/sqlcipher_db/paths`（`sys.path.insert` 项目内 import，沿用现有测试的做法）
- roster、calib 等运行时配置放 `~/.wechat-monitor/`（0600 目录，含 key，勿入 git）
- 提交前跑 `python3 -m unittest discover -s tools/wechat-send/tests` 与既有 `tools/wechat-monitor/tests`
- 本仓库目前未 git init：Task 1 先初始化

## Review Focus

预期行为（每行由标注 Task 的测试钉死）：

1. **粘贴文本含换行/尾随空白**（Markdown 报告常态）→ 不得触发额外发送或截断：paste 序列中途不发 Return；发送文本 strip 尾部空白；换行原样进输入框 — Task 4 `test_paste_cmd_contains_no_return_key`、Task 5 `test_multiline_text_sent_as_single_message`。
2. **备注重复或查无此人**（roster 配错）→ 发送前拒发 exit 2，绝不"就近选第一个搜索结果" — Task 3 `test_find_remark_ambiguous_and_missing`。
3. **db_keys 过期**（重新登录/换 key 后）→ 校验环节报错即拒发；`--force` 才允许盲发且横幅警告 — Task 5 `test_stale_keys_refuse_without_force`。
4. **微信未运行** → 立即拒发 exit 2，不做任何输入注入 — Task 5 `test_refuses_when_wechat_not_running`。
5. **并发/与人工聊天冲突** → flock 串行；`--nowait` 直接 exit 4；持锁期间 GUI 独占 — Task 5 `test_lock_serializes_and_nowait_exits`。

### Task 6c: row-target 机制适配（6b 联机实测结论落地）

背景（见台账 6b 事实）：微信 Linux 4.1.13 的搜索胶囊位于标题拖拽带内，点击不能聚焦（搜索路线实测出局）；Enter 不存在可用键名，**发送 = 点击发送按钮 (1391,866)**；输入框在点击会话行后自动聚焦；`--repeat N backspace` 是可靠清空输入的手段；会话列表随新消息实时重排 → 目标必须置顶，roster 存置顶行 y 坐标。

**Files:**
- Modify: `tools/wechat-send/roster.py`
- Modify: `tools/wechat-send/wxsend.py`
- Modify: `tools/wechat-send/tests/test_roster.py`、`tests/test_wxsend.py`（钉死测试按新序列重写；gui_driver/calibrate/dbverify 零改动）

**Interfaces:**
- Produces:
  - `Target(key, kind, ident, row: int | None = None, wxid: str | None = None)`（load_roster 校验：`row` 存在时必须 int 且 0≤row<screen 高；`wxid` 存在时非空 str；旧条目缺字段仍合法=None）
  - wxsend 序列（row 模式，所有可发送目标必须带 row）：
    focus(true) → open_search(ident=str(row)) → paste(text="") → select_first(=清输入模板) → paste(text=body) → send(=按钮点击模板)。模板全在 calib.json，本任务不动 gui_driver。
  - `_precheck`：user 且 roster 有 `wxid` → 跳过 find_remark，表=expected_table(wxid)（FP2 的备注唯一性仍对**无 wxid 的 user 条目**生效）；user 无 row → REFUSE exit 2（消息含 "row"）；group 的 roster `search` 字段故事退役——group 同样要求 row（缺 → exit 2），原 group-search 拒发测试改写为 group-row 测试；`main()` 里读 raw "search" 的分支删除。
- Consumes: 现有 `expand_steps`（{IDENT} 承载行坐标字符串是其既有语义的合法用——占位符=整 argv 元素，本就用它做过搜索文本）

- [ ] Step 1: 重写钉死测试（RED）：happy path 的 runner argv 序列（含 open_search 的 "141" 与 paste("")）、user 无 row 拒发、group 用 row 不再要 search、wxid 直连表名（contact.db 假件不被调用）、row 非法类型 ValueError、多行 body 单消息不变
